# 阅读器排版阶段

`runLayoutFit` 负责整篇求解或整篇恢复缓存。新增排版规则应按依赖放入以下阶段，不能单纯追加一个“最终处理”。

1. `fitLayoutPages`：先撤销上次的行距释放，再进行公式初步缩放、文字字号拟合及引擎内避碰；随后确定公式最终尺寸，再检查这些尺寸对文字的影响。两轮安全检查分别保护文字求解和公式扩展后的几何，不在这次调整中合并。
2. `finalizeLayoutTypography`：先完成双栏候选段落和独立文字区域的正文样式继承，再执行 `releaseBodyLeading`，最后应用用户手动字号。样式继承沿用自身的碰撞检查；行距释放之后不得再自动缩字、压行距或扩展公式。
3. 保存完整拟合快照及更新显示缩放。恢复快照时仅重建公式显示几何并检查代码块，不重复正文拟合、样式继承或行距释放。正常求解和调试入口共用同一收尾函数。

## 独立摘要与普通多行文本的起步行距

- 这两类独立文本以 1.30 作为字号拟合阶段的行距下限，再迭代各自字号。现有字号搜索与碰撞算法不变。
- 只对明确识别的独立摘要及普通多行文本生效；选择器交叉命中的正文、已继承正文样式的块、列表、标题和题注沿用原拟合参数。
- 1.30 不是覆盖全流程的强制下限。后续公式尺寸变化、样式继承及最终避碰仍沿用已有保护，必要时可局部压回 1.10。正文统一字号的求解不使用这项起步参数。
- 固定框内预留更多行距可能让这两类文本的字号略小。摘要之后仍可按下面的规则，在字号不变时向 1.35 释放。

## 正文与摘要行距释放

- 统一目标为 1.35；现有行距已更大时保留原值。
- 作用于译文正文流、成功继承正文样式的段落，以及明确识别的摘要流或独立摘要块；摘要保持原分类，不加入正文统一字号组。不按行数或公式密集标签排除。
- 正文的实际可见内容必须已经落在自身原始框内，且无碰撞；否则跳过。框顶沿用现有文字测量的 1.5 源像素字形容差，框底和左右不额外放宽。
- 固定字号与位置，以实际文字及行内公式的几何测量增加行距，同时保护框的四边、页面边界和邻近块。空间不足时保留最后一个安全行距，不要求填满框。
- 释放结果不反馈给字号求解。快照同时保存释放后的行距和释放前的行距；重新求解前先还原原值，避免累积影响字号。公式间正文仅在释放成功时覆盖其紧凑 CSS，恢复快照时保留这一效果。
- 手动字号在自动流程完成后应用，之后不做自动避碰约束。规则版本改变只使显示拟合及旧字号记忆失效，不修改解析结果或译文缓存。
