# 排版模式图片文字翻译

日期：2026-10-26。首版面向水平文字、背景较均匀的图内标签。

## 输入与共用翻译

排版阅读工具栏在“翻译表格”右侧提供“翻译图片”，两者作为一组保持同行，统一在此切换。`translateImages` 首选项默认开启。取消勾选立即隐藏图片译文，保留 OCR 和译文缓存，后续正文翻译不调用图片 OCR；重新勾选优先显示缓存，缺失时询问是否只补翻图片。补翻沿用 API、网页端或机翻引擎及全文上下文，不重译正文和表格。已有 PDF 的显示变化沿用表格的更新确认及旧批注保护；取消更新时保留旧附件，阅读器显示与 PDF 生成身份分别记录。

排版翻译从 `image_body` / `chart_body` 提取图片，跳过表格、页眉页脚及公式图片。图片 OCR 优先采用本轮传入的当前解析服务设置；未传入时沿用文献记录的 `parseProvider`，再回退到默认设置。Paddle 使用 PP-OCRv6，MinerU 使用 `pipeline`。不会因为另一家已保存令牌而改变选择；所选服务缺少令牌或请求失败时保留原图，不跨服务兜底。已有成功 OCR 和译文缓存继续复用；切换服务时仅补识别旧缓存中为空的图片，同一服务的空结果不反复重试。Paddle 保留完整图片的既有页内排布，将多页统一提交为一个任务，只有超过文件大小或页数限制才拆分；MinerU 将多张图片的文字裁片共用页面，每次最多提交二十页裁片。图片 OCR 使用单独生成的临时 PDF，绝不与文献 PDF 合并，也不改写文献原文件或解析输入。

图片文字使用 `image_labels` 记录，沿用表格的 `cells: [[索引,文字]]` 协议。在正常排版翻译输入中依次追加：正文、表格记录、图片记录。API、网页端和手动回答使用相同的短索引与保护标记，联网／Edge 机翻则把单行文字接入同一次 `translateRecords`。大文档仍按原有字符和记录数量规则自然分批，没有图片专用的模型请求队列。图片数字、编号、公式等保护规则复用表格处理，不经过正文的公式引用修正规则。

老文献显式启动排版翻译时可以补充缺少的图片记录：正文和表格仍有效则直接复用，只把缺失的图片文字加入现有请求，全文 Markdown 继续作为上下文。普通重开只读取缓存，不主动调用 OCR 或模型；不要求重新解析。单篇智能体任务可通过 `translateImages: false` 跳过本轮图片识别与翻译。首版没有新增设置页或额外的图片翻译窗口。

图片翻译在启动排版翻译或生成手动命令时按开关设置尝试，图片单独补翻使用同一服务绑定规则。MinerU 仍可能将图片主体整体分类为图表，导致内部标签缺失；只翻译实际返回的 OCR 文字，不推断补齐。

## 发给模型的编号

模型只接收表格短 ID `T1、T2…` 和图片短 ID `I1、I2…`。每个 `cells` 中只列待翻译文字，编号从 1 连续递增；例如原 OCR 行号为 `0、7、8、9` 的四条文字，发送为 `1、2、3、4`。原始行号、坐标、完整来源指纹和缓存 ID 保留在本地，回答通过映射恢复，不改动旧缓存。`⟦0⟧` 等仍是原有数字／公式保护标记，与行编号无关。

手动命令在任务级提供一个短 `request` 码，每轮回答的 JSONL 首行只回传一次。该码绑定文献、目标语言及完整输入，短 ID 重名时仍能拒收另一篇文献或旧来源的回答；旧命令生成的长 ID 回答仍兼容。API 请求由当前请求上下文绑定，不要求模型额外返回任务码。自动请求、手动翻译、续译及表格补翻均使用相同的短 ID 和连续编号。

## 强制 OCR

MinerU 继续使用已有 `isOCR` / `is_ocr` 参数。实测 `vlm` 加 `isOCR: true` 仍未提供完整图内文字，不能把强制页面 OCR 当作完整图片 OCR。

随后另用真实 `pipeline + isOCR: true` 解析同一两页案例，第二页 `model.json.layout_dets` 返回正文／图注 OCR，但仍没有流程图六个内部标签，也没有统计图的内部轴标签。不能据此把切换解析模型作为 MinerU-only 图片翻译的可靠替代。该次只调用 MinerU，没有调用 Paddle。

2026-10-29 补充实验：把 `flow.png`、`chart.png` 分别独立上传，比较 `pipeline` 与 `vlm`，均开启 `is_ocr`，关闭表格及公式识别。两种模型均返回流程图六个标签；统计图仍只返回标题，内部轴标签、组名等缺失。因此补充路径使用 `pipeline` 原始 `model.json.layout_dets` 中的 `ocr_text`（含置信度），不使用 VLM 图表描述或文本块摘要。

同日通过实际 `ImageTranslationService` 把两图合成双页 PDF，一次 MinerU 请求返回流程图六行、统计图标题一行，重复调用复用 OCR 缓存，Paddle 调用数为零。证据保存在 `output/mineru-image-probe/batch-summary.json`。原始 OCR 坐标按 `page_info.width/height` 归一化，逐页核对数量和零起始页码；临时 PDF 与解压结果在完成或失败后清理。没有改写已有文献的解析结果或译文。

### 强制 OCR 对照与图片识别扩展实验

同日继续完成 18 个真实 MinerU 请求、64 个输入页，全程没有调用 Paddle 服务。服务返回版本为 `3.4.4`，`pipeline` 返回 `_backend: pipeline`，API 的 `vlm` 返回 `_backend: hybrid`。两页受控样例及三张真实论文图片仅用于可行性验证，不能视为通用准确率基准。参数、耗时、原始 model/layout/Markdown 与分析保存在 `output/pdf/mineru-ocr-matrix/`，汇总为 `analysis.json`。

强制 OCR 开关比较使用完全相同的文件。包含扫描表格页和原生文字加图片页的双页 PDF，在两种模型下，开关前后的最终 Markdown 都逐字节相同，也都没有流程图内部六行和统计图内部标签。`pipeline` 最终的十一行文字及行框相同，但原始 model 的空 OCR 行在强制模式下有文字，部分最终 span 的置信度不同；自动模式后处理仍可补充识别，不能以原始 model 的空行判断最终正文缺失。`vlm` 的 `_ocr_enable` 从 false 变为 true，十一行文字相同，仅一行的文字和行框同时完全一致，其余行框有差异。纯图片组成的双页 PDF 在两个模型下，开关前后的最终 layout 都完全一致，均只返回流程图六行和统计图标题一行。此样例没有证明强制 OCR 会扩大图片内部识别范围。

`pipeline` 源码先用版面分类选择文本区域，再执行 OCR；`image`、`chart` 不属于普通文本区域，嵌套在更大块中的文本候选也可能被移除。因此关闭表格／公式识别不等于关闭图片／图表分类，强制 OCR 也不等于对整图所有像素执行无条件文字识别。

| 送入 MinerU 的统计图输入 | 实际返回 |
| --- | --- |
| 原 PDF 中的图片、单独完整图片 | 只有标题 |
| 五条重叠水平裁片 | 标题、Control、Treatment、ACCURACY；中央注释仍缺失 |
| 四个重叠方形裁片 | 仅截断的标题，效果更差 |
| 去除长线和大色块，保留文字笔画及原位置 | 十二行，含五条英文标签和七条数值 |
| 文字候选小块重排成文本页，保存小块到原图的映射 | 同样识别十二行，能映射回原坐标 |

真实论文的三张图片进一步暴露了分类限制：完整示意图、曲线图及复杂反应图在 `pipeline` 下均无普通 OCR 行；水平裁片仅从反应图返回 Vaporization。局部去图形后继续保留原排布，也不能稳定绕过图表分类。去除大图形并把文字候选排成普通文本页后，示意图返回九行英文标签；曲线图返回 Exp. data 和 Mole fraction of Oxygen 等文字，但竖排轴标题出现碎片；反应图返回 Regime 1/2/3、Vaporization end、O2 depletion 等文字，但彩色底白字仍有缺失，化学式也有误识别。置信度高不能单独证明文字完整或符号准确。

可行的扩展路线是：对识别副本提取文字候选 → 排成普通文本页 → MinerU pipeline OCR → 通过候选映射回原图 → 翻译可靠文字 → 按原图背景和数值保护决定是否覆盖。映射按唯一候选的中心及重叠核对，不能要求 OCR 框严格包含在候选内，因为真实 OCR 框存在外扩；展示框仍取原候选框。该路线目前是实验原型，没有加入默认运行路径，也没有改写原图或已有文献缓存。

真实示意图的九行标签已通过 Gemini `gemini-3.5-flash-lite` 完成中文翻译。按边缘背景一致性筛选后实际覆盖五行，其余四行保留原文，中心 `Al₂O₃` 和图形结构保留。证据为 `translation-real-proof.json`、`render-proof.json` 与 `real-comparison.pdf/png`；这些是独立实验产物，并非正式阅读器视觉验收。当前样例各任务从提交到轮询完成耗时 7.6–20.3 秒，包含网络、排队及轮询，不能据此排名模型速度；小块处理也会增加解析页数与额度消耗，应先控制候选数量和每页容量。可复用的最终预处理实验脚本为同目录 `prepare_image_ocr.py`，接受图片路径及 `--output`，输出识别副本、小块重排 PDF 和原坐标映射。

Paddle 的 `isOCR: true` 现在实际传递为 `useOcrForImageBlock: true`；默认解析行为保留。强制 OCR 能在图片块的 `block_content` 中返回文字，但只有整图坐标，不能用于逐行覆盖。图片翻译因此独立补充 PP-OCRv6 坐标，而不把解析器的图表理解结果当作准确的图内文字清单。未强制打开 `useChartRecognition`，避免图表结构推断覆盖原有分类和数值。

## 缓存与保护

### MinerU-only 图片文字补充（2026-10-29）

默认链路已接入文字裁片识别：文献使用 MinerU 解析时，在本地 Canvas 中对图片副本提取小笔画候选，保留来源坐标，再跨图片排成普通文本页。处理副本长边不超过 1600 像素、像素数不超过 230 万；每图最多八十个候选，中间裁片画布高度不超过 2400 像素。没有候选或副本处理不可用时保留原图，不逐图追加请求。此处理不需要 Python、OpenCV、额外模型或用户另行配置服务。

共享识别页采用按高度整理的棚架排布，最多 712 像素宽、1000 像素高，裁片保持原尺寸；横向留 64 像素间隔、行间留 32 像素间隔，过宽候选不强行缩小。每次提交最多二十页，文件中只有文字裁片，没有完整原图或文献页面。每条返回行必须唯一匹配到所属图片的裁片，按行框映射回原位置；无法确认位置的行跳过。原解析 PDF 从不参与这一步的生成或保存。

裁片返回的 OCR 行必须满足原有置信度、方向及有效框条件，并唯一匹配到一个本地候选。以每一条 OCR 行自己的位置反映射，不将同一候选中其他未识别的文字一起擦除。新行与原有行发生重叠时优先保留原有行。数字、公式以及无法分离的重叠标签保留原文；复杂曲线、旋转文字及彩色底白字仍有漏识别。

OCR sidecar 维持版本 1，新结果使用 `strategy: "shared-text-crops-v2"`。旧 `text-crops-v1` 结果继续直接复用，不因拼页方式改变而重新消耗额度。打开已有文献只读缓存；用户显式启动翻译时，未补充过裁片的旧 MinerU OCR 缓存可补充一次识别，保留原有行。补充失败返回旧缓存，不改写旧文件。Paddle 缓存继续按原有条件复用。

初版隔离实测为四张图片、八个 OCR 页，记录保存在 `output/ocr-compare-live/packed/`。跨图片拼页后，同一四图的四十三个裁片共用一页，仅提交一个 MinerU 任务，Paddle 调用为零，重复调用命中缓存。流程图返回六条文字及两个箭头，统计图保留四条可翻译英文标签，论文示意图返回九条文字，曲线图新增部分轴标题和图例文字。箭头和数值仍走原有文字保护规则。真实服务记录保存在 `output/ocr-shared-strokes/`。这是小样本可行性验证，不是通用准确率基准。

### 笔画补色与字色保留

阅读器从原图像素中提取接近字高的笔画连通域，排除长引线、跨出区域的图形及已知数字／公式框；字母圆点和抗锯齿边缘仅在文字附近补充。局部背景由文字区域上下边缘的中值样本插值，纯色或浅渐变背景只替换文字笔画，其他像素复制原图。译文区域收紧到文字本身，避免把中文居中写到左侧引线上；字色采用原笔画颜色。复杂纹理或无法确认的区域仍保留原图，不生成图形内容。

上述处理仅生成内存中的背景补片和 DOM 译文层，不覆盖磁盘图片。`image-render-v2` 显示摘要使旧图片译文也可直接使用新补色并更新导出结果，无需重新 OCR 或翻译。正式阅读器与 PDF 导出使用同一补片；定位使用小数 CSS 尺寸，避免整数舍入露出英文细边。三页正式译文和对照 PDF 位于 `output/pdf/mineru-shared-strokes/`；原 PDF、布局源文件及已有正文译文在测试前后保持一致。

### Paddle 完整图片共页

Paddle 使用完整原解析图片，按原始像素宽高排入最长边约 2000 像素的识别页，图间保留 32 像素空隙，不在本地缩小图片。超出页尺寸的大图单独成页。PDF 中的图片宽高按像素乘以 0.5 放置，来源图片不重新编码；返回的逐行多边形先归一化到共享页，再唯一匹配到所属图片并还原为图内坐标。跨图片或边界不明确的 OCR 行跳过。

图片 OCR 的 `textDetLimitSideLen` 设为 2000、`textDetLimitType` 设为 `max`，避免拼页后继续使用较小检测边长导致小字被过度缩小。这两个参数来自 [PaddleOCR 官方 SDK 的 OCROptions](https://github.com/PaddlePaddle/PaddleOCR/blob/main/paddleocr/_api_client/models.py)。新结果标记 `full-image-sheets-v1`；旧 PP-OCRv6 缓存仍直接复用，不因拼页方式变化而重新请求。内部保留每二十张图的页组以避免改变原页内布局，页组统一合成一个多页 PDF 提交；不再以图片数量划分云任务。超过 200 MB 或 1000 页时递归拆分，一页本身超限则保留原图并报告问题。轮询不创建新的识别任务。

2026-10-29 在隔离 Zotero 中以四张完整图片对照：单图基线为一个任务、四页，共页后为一个任务、一页，服务返回识别页为 1504 × 1773 像素，并确认检测参数为 2000 / max。流程图六行、统计图十二行、论文示意图十行与基线一致；复杂曲线图的横排轴标题、图例及数值保留，基线错误识别的竖排轴标题 `Burnte [us]` 和图线中误检的 `1` 未返回。竖排标签仍不属于当前覆盖范围；不能据此推断所有图片都没有识别差异。第二次执行直接复用缓存。原始 JSON、两份输入 PDF 和对照数据保存在 `output/paddle-image-sheets/`；测试 fixture 仅保留文字、坐标及图片映射，不包含 Token 或结果下载链接。

Paddle 共页结果还通过正式阅读器和 PDF 导出验证：同一套图片笔画补色显示了流程图六条、统计图四条及论文示意图九条译文；与 `87%` 框重叠的标签继续保留原文，化学式 `Al2O₃` 进入原有保护区域。原文 PDF、布局和正文译文在前后核对不变。导出结果位于 `output/pdf/paddle-image-sheets/`。

### 其他取色、去底色逻辑的边界

| 场景 | 实现 | 与图片笔画补色的关系 |
| --- | --- | --- |
| 图片内翻译标签 | `LayoutImages.restoreImageLabel`、`fitLayoutImageLabels` | 新增算法；MinerU 与 Paddle 共用，阅读器及译文 PDF 共用 |
| 正文、标题、图注及表注排版 | `samplePerimeterColor`、`eraseAndPatchPageBackground` | 原有区域取色及整块擦除，清除旧文字后重绘；未改成图片笔画算法 |
| 公式、公式标号重绘 | `registerBlockErasureItem`、`eraseAndPatchPageBackground` | 原有扩框及纸色覆盖规则，未改动 |
| 翻译表格底色 | `sampleTableBackground` | 原有整表主底色采样及文字对比度处理；没有逐单元格纹理修复 |
| 阅读主题的图片及页底图 | `ReaderImages.applyThemePixels` | 原有白底透明化及主题色显示副本；图片翻译覆盖层主动跳过该处理，打印使用原色底图 |

这些处理都作用于派生画布或 DOM，不回写原文 PDF。Paddle 拼页优化没有扩大任何取色或去色算法的适用范围。

原解析和原图片保持原样，新增文件位于文献缓存内：

```text
image-ocr.v1.json
layout-translation/image-translations.<语言>.v1.json
```

OCR 和图片译文绑定源布局指纹及解析版本，防止重新解析后相同框坐标复用旧图片文字。请求 ID 额外绑定图片 OCR 文字和坐标摘要，旧手动回答不能套用到新的识别行。图片译文在基础模型构建后内存附加，不写入 compiled-model 或正文译文。已有完整图片译文不会被不完整的新回答覆盖；重新解析时原数据随现有解析历史归档。

图片译文摘要进入显示缓存与 PDF 导出标识，只有图片内容变化也能生成对应的新 PDF。沿用现有 PDF 附件发布和批注保护。读取图片资源按内容识别 PNG/JPEG，兼容服务返回扩展名 `.png`、实际编码为 JPEG 的资源。

重新翻译时，正文、公式替换、表格、图片译文和完成记录先准备好，再复用现有文件回滚方法一起替换旧结果；写入或替换文件失败时保留完整旧版。API／网页端、机翻的强制重译和手动导入使用同一保存方法。普通首次翻译保留已有的分段保存行为。这个调整只改变保存顺序，不增加模型调用、重试或译文验收条件；个别表格或图片回答缺失时仍保留已有结果／原图，正常保存可用正文。

## 显示与限制

译文侧保留原图，仅在原图内部覆盖可靠识别出的单行文字。Paddle 置信度低于 0.85、旋转、越界或无有效多边形的行跳过。MinerU 同样要求至少 0.85 置信度，但返回的是轴对齐框，无法像 Paddle 多边形一样判断轻微倾斜；跳过明确旋转、多行、竖长框及越界框。逐行提取文字笔画并按附近背景补色，不能确认文字区域时保留原图；按文字区域尺寸测量译文，必要时缩小字号，低于最小字号或仍放不下时保留原文。纯数字、明确单位和包含公式的行保持原图像素。

译图保留原配色，避免主题融合导致背景补色与原图不一致；其他图片仍走已有主题处理。原文侧、图片预览和图片提问使用原图；阅读器和 PDF 输出使用同一份译文覆盖层。此版本没有复杂纹理修复、旋转文字翻译、图表重建或语义补字。OCR 漏掉的文字保持原文，不推断补齐。
