# Edge 排版全文测试及修复计划

## 测试结果

同一篇 Xian 等（2024）论文，文档 ID 1-CK2YDIKK，Zotero 10.0 隔离测试库。完整读取 layout.json，通过实际 extractRecords → translateWebMachine → translateRecords → normalizeWebMachineRecord → buildModel 流程，不复用译文。输入文件复制到诊断目录，持久化结果也只写入该副本。

生成 14 页阅读模型；其中 13 页有可翻译记录，共 112 个记录、112 个输出。78 次实际 Edge 调用全部成功，其余记录由标题映射、无需翻译等本地规则处理。33 个最终保持原文的记录均为 (a)、(b) 等子图标签。未进行 PDF 导出或逐页视觉验收，完成范围是全部排版翻译记录及阅读模型构建。

对记录正文中的 34 个行内数学片段做精确比对：一个片段缺失，另一个发生重复。缺失的是解析器标为公式的 `\\(( \\mathrm { i . e . , }\\)`，本质上是误归类的文字片段，不能表述为一条真正数学公式丢失。第 6 页 p006_b0002 的 `2^14 × 0.1` 对应保护标记输入一次、输出两次，译文还把 min 译为“最小值”。

第 1 页摘要 p001_b0008 将 −5/3 损坏为 `−<b9000>/3`，数字 5 被移到后文；第 2 页 p002_b0002 出现 `PP9004></b9004>`、年份损坏及重复语句。这些问题已存在于 Edge 返回值，后处理没有有效拦截。

流式全文前次测试：116 次调用，79 次无冒号输入中 21 次新增冒号（26.6%），11 次返回异常标签，漏掉 14°C。两种模式的分块与输入不同，不能据此推断排版模式的模型更可靠。两次测试都只覆盖同一篇文献的一次运行。

## 修复顺序

1. **先校验完整性，再接受结果。** 在保护标记恢复前核对每个标记出现次数，检测缺失、重复、未知标记，以及原文不存在的 b9000 类标签和碎片。失败进入重试，不能因非空字符串就视作成功。补齐当前 qualityIssues 的漏检；把调用成功与质量通过分别记录。禁止以删除异常标签的方式掩盖数字或语句损坏。
2. **增加有界质量重试。** 当前恢复主要处理异常和空结果；把非空但损坏的输出接入恢复流程。先按句子切分，保持受保护片段完整；仍失败再使用现有“保护片段原样拼接、只翻译周围文字”的策略。限制重试次数，记录失败块及原因，不自动切到联网服务。无法安全恢复时保留该块原文、标记待核对，不覆盖该块已有合格译文，也不宣称全文质量通过。
3. **优化排版输入。** 只在内存中合并段落内部的 PDF 软换行；基于行信息谨慎修复行尾断词，保留列表、真正的连字符、公式边界和段落结构。使用本次长段落对比原输入与规范化输入，评估异常标签、漏译和重复变化；不要预先假定换行是唯一原因。
4. **再处理新增冒号。** 统计冒号与保护标记的邻接关系；优先通过质量重试减少新增标点。仅在有明确原文对应关系时清理保护标记附近的多余冒号，保留比例、时间、URL、引导公式和原有冒号。不能全局删冒号，也不能把所有新增冒号都认定为错误。
5. **保护历史缓存。** 不迁移或改写旧 layout.json、compiled-model.json、translations.*.json 和 Markdown。新增校验结果使用旁路元数据，旧文献直接可读；缓存不能因规则版本变化被强制重新翻译。历史结果中的语义缺失不做猜测补写；按用户操作对问题块重译，成功后按块安全发布并保留原结果。

## 验收

- 固化两次实测的缺失、重复、异常标签、日期时间、比例冒号、正常上标、换行断词等回归样例，同时验证正常结果不被误改。
- 重跑同篇文献的完整流式与排版流程，并重复运行一次观察稳定性。要求所有受保护片段数量一致、无新增异常标签、无静默接受的损坏块，失败必须可定位；人工复核日期、数字、单位和抽取的长段落。新增冒号率仅为诊断指标，不作为无条件删除依据。
- 对旧缓存做前后哈希核对，确认无需重译即可加载；对本次生成的排版阅读模型再做逐页视觉检查，重点看第 1、2、6 页、公式编号和图注。若测试 PDF 导出，再单独验证导出文件。
- 运行 npm run validate，经默认开发任务构建并启动隔离 Zotero。诊断代码本次已完成该验证及构建，以上翻译行为修复尚未实施。
